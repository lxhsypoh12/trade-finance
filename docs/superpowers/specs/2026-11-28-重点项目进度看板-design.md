# 重点项目进度看板 — 设计文档

日期：2026-11-28
状态：待用户批准（四项问答已拍板：三区块布局 / 勾选随记录走 / 加更新时间列 / 暂不加飞书提醒）

## 意图与原因

每周五下班前各经办同事更新各自重点业务进度，领导每周掌握各项目实施动态，并在周例会投屏展示。现状是三阶段统计表记录全量业务，无法突出"重点"，也没有进展/障碍的登记处。本功能给三阶段表加"纳入重点项目看板"勾选，勾上的记录自动汇入新看板，看板叠加可编辑的进展/障碍列与多维筛选。

## 目标

1. 主页「📋 贸易业务统计汇总」板块新增第 8 张卡片「🎯 重点项目进度看板」（第三行业务模式指南旁，板块末尾——Claude 定，不打乱既有卡片顺序）
2. 三阶段统计表各在最后加一列"纳入重点项目看板"复选框（bid 在「操作」列后、win 在「预计利润」后、done 在「计入利润」后），勾选即存库（照 profit_included 列既有模式，onchange→cellUpdate 布尔分支）
3. 新看板视图：顶部全局筛选条＋投标/中标/完成三区块上下排；每区块标题带条数
4. 看板数据从 trade_stats 实时读取（`key_project=eq.true` 服务端过滤），**非快照复制**——统计表改字段，看板刷新即同步
5. 各区展示列（全部只读）：
   - 投标：项目名称、区域、城投公司、业务类型、业务规模、投标时间、负责人
   - 中标：项目名称、区域、城投公司、业务规模、业务类型、中标时间、负责人、贸易方
   - 完成：项目名称、区域、城投公司、业务规模、业务类型、完成时间、负责人、贸易方、实际利润、收入合计、支出合计、待回款金额
   - 三区行尾统一追加三列：项目进展（可编辑）、障碍（可编辑）、进展最后更新（只读）
6. 完成区计算口径（单位万元）：实际利润=effProfit(r)；有 profit_detail 时 收入合计=Σincome、支出合计=Σexpense、**待回款金额=Σ income[k] 其中 payee[k].verified≠true**（没填过收款信息的收入项视为未核对，计入待回款）；无 profit_detail 时 收入合计=actual_revenue||0、支出合计=actual_cost||0、待回款=收入合计（全额未核对）
7. 可编辑列：项目进展/障碍为 textarea（rows=2，照 errorlog 惯例），onblur 保存，PATCH {progress|obstacle, progress_updated_at:now, updated_at:now} 一次请求；「进展最后更新」显示 progress_updated_at 格式 YYYY-MM-DD HH:mm，空值显示灰色「尚未更新」
8. 筛选条五个下拉：区域、城投公司、业务类型、负责人、贸易方。交互（用户指定关键词联想）：
   - 点开=面板：搜索框＋复选框选项列表（选项=当前看板行该字段 distinct 值，业务类型按 BIZ_TYPES 顺序、其余按中文排序；贸易方选项仅取自中标/完成行）＋「清空」
   - **搜索框输入关键词 → 选项列表过滤为"包含关键词"的值，并自动全部勾选**（替换式：勾选集=匹配集；此后手动增减为叠加式微调）——例：负责人有 徐雪/李昕\/徐雪/胡翔\/徐雪/金诗佳\/徐雪，输入"徐雪"四个全勾
   - 匹配规则：子串包含（含"/"复合值），大小写不敏感
   - 五个筛选之间 AND；同一筛选内多选 OR；**贸易方筛选只作用于中标/完成区块，投标区不受其影响**（投标区无贸易方列）
   - 收起态按钮显示摘要：无勾选=「全部」，有勾选=「徐雪 等4项」/单项直接显示值；任一筛选生效时筛选条尾部出现「✕ 清空筛选」
   - 字段值为空的行：该字段筛选生效时不匹配任何勾选值→被过滤掉（与发票看板惯例一致）
9. 迁移携带：投标→中标（两条路径）、中标→完成迁移均整行复制，key_project/progress/obstacle/progress_updated_at 自动随记录进入新阶段（用户拍板"勾选随记录走"，零额外代码；迁移后进展文本保留，供下阶段经办参考）

## 非目标

- 不做飞书周五提醒（用户拍板暂不加；现有 17:30 日报脚本零改动）
- 不做看板 Excel/PDF 导出（例会投屏直接用网页；如日后需要另立任务）
- 不做进展历史版本/周快照（只显示最近一次进展与更新时间）
- 不做按人锁定/登录鉴权（全系统无登录体系，任何打开网页的人可编辑，与现状一致）
- 三阶段表既有列、财务看板、发票看板、飞书推送零改动

## 反目标（出现即失败）

- 勾选"纳入"后看板不出现该记录，或取消勾选后仍残留
- 进展/障碍编辑丢失、或编辑进展却把统计表字段覆盖
- 筛选"徐雪"漏掉"李昕/徐雪"类复合值记录
- 待回款金额把已核对完成的收入项算进去
- 迁移后勾选/进展丢失
- 数据库字段未加时页面白屏（应显示友好提示）

## 约束

- 纯前端单文件，改动限于 `贸易金融业务管理系统（Supabase）.html`（同步 index.html）＋测试（e:\tmp\sdd-test）
- **前置：用户需在 Supabase SQL Editor 执行一次加列 SQL（开发方提供＋大白话指引），执行前开发方先落地当日 trade_stats 全表备份**：
  ```sql
  ALTER TABLE trade_stats ADD COLUMN key_project BOOLEAN NOT NULL DEFAULT FALSE;
  ALTER TABLE trade_stats ADD COLUMN progress TEXT DEFAULT '';
  ALTER TABLE trade_stats ADD COLUMN obstacle TEXT DEFAULT '';
  ALTER TABLE trade_stats ADD COLUMN progress_updated_at TIMESTAMPTZ;
  ```
  加列带默认值，不改动不删除任何现有数据；匿名 RLS 策略已覆盖新列（表级策略）
- 字段未加时的降级：看板 GET（带 key_project=eq.true）失败→看板区显示提示「数据库尚未添加看板字段，请先执行加列 SQL」；三阶段表勾选列仍显示但勾选保存失败沿用既有静默模式（不额外处理，部署顺序上先 SQL 后使用）
- 每 Task 提交前 cp index.html；全量回归绿才推送

## Approaches

| 方案 | 说明 | 结论 |
|------|------|------|
| A. trade_stats 加 4 列（选定） | 看板=同表 key_project=true 过滤视图，一次 GET；迁移整行复制天然携带勾选与进展 | 与"删旧插新换 UUID"的迁移模型兼容，零 join、零孤儿 |
| B. 独立 key_projects 表按记录 id 关联 | 规范化更好、可留历史 | **否决**：迁移=删旧行插新行（新 UUID），关联 id 每次迁移即断线，进展变孤儿；修复需另造稳定项目标识，复杂度不成比例 |
| C. 进展存 localStorage | 零数据库改动 | 否决：多经办/领导各自浏览器数据不通，违背"共享看板"本质 |

## Claude 决定（用户可推翻）

- 卡片放板块末尾（第三行、业务模式指南旁），图标 🎯
- 视图 id：`view-stats-keyproj`；对象名 `KeyProjStats`（照 LoanStats/InvoiceStats 独立对象惯例）；showView 注册与 exportPDF others 列表同步
- 看板行排序：各区块内按本阶段时间字段降序（done 沿用 doneTimeVal 口径），时间空/不可解析排最后
- 三阶段表新列表头文案「纳入重点<br>项目看板」（两行换行防撑宽），列宽约 70px，复选框 class=kp-cb
- colspan 联动：bid 报价展开行 10→11、bid 空表 10→11、win 空表 14→15、done 空表 15→16
- 进展/障碍列宽约 180px；更新时间列约 110px
- 看板加载：单次 GET `trade_stats?select=*&key_project=eq.true`（不带 stage，三区前端分组）；进入视图每次重拉（照 FinanceStats 惯例，不做会话缓存）
- cellUpdate 布尔分支扩为 `field==='profit_included'||field==='key_project'`

## 实现要点（留给构建者）
