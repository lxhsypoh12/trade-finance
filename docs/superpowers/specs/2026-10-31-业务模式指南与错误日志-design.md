## 1. 背景与意图（为什么做）

同事在开展不同类型贸易业务时出过一些错误，原因有二：
1. 对该类业务的整体流程不熟悉，漏掉细节；
2. 粗心，重复踩别人踩过的坑。

因此在贸易金融业务管理系统中新增两个互相联动的模块：
- **业务模式指南**：用流程图展示每类业务的全流程和各环节注意事项，解决"不熟悉流程"；
- **错误日志总结**：记录历史上发生的重要错误（内容、后果、解决方案），解决"重复犯错"。

两个模块通过"业务类型"联动：在指南详情页可一键查看该业务类型历史错误记录。

### 4.2 业务模式指南模块

**视图结构**（新增 2 个 view）：
- `view-guide`：业务模式卡片列表页（返回主页链接 + 3 张模式卡片，样式复用 home-card 风格）。
- `view-guide-detail`：**单个**详情页容器，根据点击的卡片动态渲染内容（`Guide.showDetail(key)`），避免每个业务写一个 view。

**数据源**：流程图内容以 JS 常量 `GUIDE_DATA` 硬编码在 HTML 中（用户已选"固定流程图"方案），结构：

```js
var GUIDE_DATA = {
  'entrusted-pay': {
    title: '受托支付',
    icon: '🔀',
    linkedBizTypes: ['跑量/受托支付'],   // 关联 error_logs.biz_type，用于联动筛选
    steps: [
      { key: 's1', name: '环节名称', desc: '环节说明',
        actor: '',      // 预留：经办方（我司/银行/城投/供应商），按素材填写
        docs: [],       // 预留：本环节资料清单
        branch: null }, // 预留：分支/退回走向说明，形状以手画素材为准
      // ...
    ]
  },
  'city-cp-pledge': { title: '城投商票质押贷款', icon: '🏦', linkedBizTypes: ['商票质押贷款'], steps: [...] },
  'personal-cd-pledge': { title: '个人存单质押贷款', icon: '💳', linkedBizTypes: ['存单质押贷款'], steps: [...] }
};
```

注意：**注意事项不存在 GUIDE_DATA 里**（那是硬编码），而是存在 `guide_notes` 表（见 4.4），按 guide_key + step_key 关联到具体环节，这样用户才能在页面上自行增删改。

**流程图呈现**：竖向步骤卡片，步骤间用 CSS 箭头（▼）连接；每个步骤卡片含：序号圆点、环节名称、环节说明、⚠️ 注意事项区（黄色提示框，内容从 guide_notes 表加载，带"＋ 添加注意事项"按钮；每条注意事项带编辑 ✎ / 删除 ✕ 小按钮）。全部用现有 CSS 变量/风格，不引外部库。

**错误记录联动**：详情页头部和底部各放一个按钮"⚠️ 查看该业务的错误记录"。点击弹出**模态弹窗**（复用系统现有弹窗样式，如完成阶段"资料"弹窗的模式），内容为 `error_logs` 中 `biz_type` 属于该指南 `linkedBizTypes` 的记录列表（只读，按时间倒序），弹窗内显示条数；无记录时显示"该业务暂无错误记录"。

**内容素材与制作方式**（用户已确认）：
- 用户为每个业务模式建一个素材文件夹（建议放在项目目录 `业务模式指南素材\` 下，如 `受托支付资料`、`城投商票质押贷款资料`、`个人存单质押贷款资料`），每个文件夹至少包含：① 手画流程图照片（至少一张）；② 一份对该照片的详细流程文字介绍 md 文件。
- Claude 依据素材制作 HTML/CSS 流程图：手画照片仅作制图依据、不嵌入页面；流程形状以手画图为准，GUIDE_DATA 已预留 actor/docs/branch 字段，素材中若出现分支/退回/多方经办，无需改数据结构即可承载。
- **注意事项不放在素材里**：上线后由用户直接在指南详情页自行增加、编辑、删除（存 guide_notes 表，多人共享）。

### 4.3 错误日志总结模块

**Supabase 新表 `error_logs`**（Step 1 由用户在控制台执行）：

```sql
CREATE TABLE error_logs (
  id BIGSERIAL PRIMARY KEY,
  biz_name TEXT NOT NULL DEFAULT '',        -- 业务名称
  occur_date DATE,                          -- 时间
  biz_type TEXT NOT NULL DEFAULT '',        -- 业务类型
  severity TEXT NOT NULL DEFAULT '中',      -- 重要程度：高/中/低
  error_content TEXT NOT NULL DEFAULT '',   -- 错误内容
  consequence TEXT NOT NULL DEFAULT '',     -- 导致后果
  solution TEXT NOT NULL DEFAULT '',        -- 解决方案
  created_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE error_logs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "允许匿名读取" ON error_logs FOR SELECT TO anon USING (true);
CREATE POLICY "允许匿名插入" ON error_logs FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "允许匿名更新" ON error_logs FOR UPDATE TO anon USING (true) WITH CHECK (true);
CREATE POLICY "允许匿名删除" ON error_logs FOR DELETE TO anon USING (true);
```

**REST API 封装**（沿用现有命名模式）：

```js
errorLogGetAll()          // GET  error_logs?order=occur_date.desc
errorLogInsert(records)   // POST Prefer: return=representation
errorLogUpdate(id,fields) // PATCH ?id=eq.{id}
errorLogDelete(id)        // DELETE ?id=eq.{id}
```

**前端对象 `ErrorLogStats`**（镜像 `LoanStats` 的交互模式）：
- `render()` — 渲染表格 + 行着色
- `addRecord()` — 新增一行并直接进入编辑模式
- `startEdit(id)` / `saveEdit(id)` / `cancelEdit()` — 行内编辑
- `deleteRecord(id)` — 删除（confirm 确认）
- `showFiltered(bizTypes)` — 供指南模块弹窗调用的只读渲染

**表格列**：操作 | 业务名称 | 时间 | 业务类型 | 重要程度 | 错误内容 | 导致后果 | 解决方案。错误内容/导致后果/解决方案为长文本，编辑态用 textarea，展示态允许换行显示。

**编辑控件**：
- 业务类型：下拉框，选项沿用系统现有 `BIZ_TYPES`（银承-回报、银承-供应链、信用证-回报、信用证-供应链、跑量/受托支付、存款、时点、商票质押贷款、存单质押贷款、其他）。
- 重要程度：下拉框，高 / 中 / 低。
- 时间：日期选择器（允许选过去日期）。
- 业务名称：自由文本（具体项目/业务叫什么）。

**行着色规则**（与贷款统计一致的色系）：
- 🔴 高：`#fed7d7`
- 🟡 中：`#fefcbf`
- 🟢 低：`#c6f6d5`

**筛选**：表格上方两个下拉筛选器（业务类型、重要程度），纯前端过滤已加载数据，可组合；另有"清空筛选"。

**排序**：默认按"时间"倒序（最新在前）。

### 4.4 注意事项存储：Supabase 新表 `guide_notes`（用户已确认：注意事项要在界面上自行增删改）

```sql
CREATE TABLE guide_notes (
  id BIGSERIAL PRIMARY KEY,
  guide_key TEXT NOT NULL,               -- 业务模式标识（GUIDE_DATA 的 key，如 entrusted-pay）
  step_key TEXT NOT NULL,                -- 环节标识（GUIDE_DATA 中 steps 的 key，如 s1）
  content TEXT NOT NULL DEFAULT '',      -- 注意事项内容
  created_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE guide_notes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "允许匿名读取" ON guide_notes FOR SELECT TO anon USING (true);
CREATE POLICY "允许匿名插入" ON guide_notes FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "允许匿名更新" ON guide_notes FOR UPDATE TO anon USING (true) WITH CHECK (true);
CREATE POLICY "允许匿名删除" ON guide_notes FOR DELETE TO anon USING (true);
```

**API 封装**（沿用现有命名模式）：

```js
guideNotesGetAll()          // GET  guide_notes?order=created_at.asc
guideNotesInsert(records)   // POST Prefer: return=representation
guideNotesUpdate(id,fields) // PATCH ?id=eq.{id}
guideNotesDelete(id)        // DELETE ?id=eq.{id}
```

**渲染与交互**：打开指南详情页时一次性拉取该 guide_key 的全部注意事项，按 step_key 分组填入各环节卡片的注意事项区；添加＝弹出单行输入（或行内 textarea）后 INSERT；编辑＝行内改文字后 PATCH；删除＝confirm 后 DELETE。交互镜像 LoanStats 的行内编辑模式，但简化为单字段。
