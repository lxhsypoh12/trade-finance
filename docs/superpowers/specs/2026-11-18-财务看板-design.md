## 1. 背景与目标

公司目前用手工 Excel 维护"贸易板块利润情况明细"：收入层从系统完成表手工抄录，成本层由财务另行统计。手工维护已出现两处数字打架（2-1 与 2-2 同项目利润不一致；2026/7、2026/9 完成的项目被填入"2季度"列）。

目标：系统内新增"财务看板"模块，实现——
1. **收入侧零录入**：项目收入及收支明细实时读完成表自营记录，自动汇总，杜绝两处数字打架
2. **成本侧系统化**：财务同事在网页上录入公司固定成本/链条费/报销费/其他支出，替代 Excel 成本层
3. **利润汇总自动生成**：项目收入 − 成本支出 − 其他支出 = 合计，按期间分列
4. **纳入利润统计勾选项**（用户新增需求）：完成表每条记录末尾加勾选框，只有勾选的记录才计入利润口径——同时影响完成表底部三个汇总（公司总利润/咨询类/自营类）和财务看板

## 4. 数据模型

### 4.1 trade_stats 新列（用户在 Supabase SQL Editor 执行）

```sql
ALTER TABLE trade_stats ADD COLUMN profit_included BOOLEAN NOT NULL DEFAULT TRUE;
```

- 默认 TRUE：现有 done 记录（审查时实时查询 35 条）及 bid/win 记录行为不变（汇总数字与改动前一致），用户主动取消勾选才剔除
- 语义：`profit_included = true` → 计入；`false` → 不计入任何利润汇总
- 代码中判断统一写 `r.profit_included !== false`（undefined/null 视为计入，兼容列未加时的缓存数据）

### 4.2 新表 finance_costs（用户在 Supabase SQL Editor 执行）

```sql
CREATE TABLE finance_costs (
  id BIGSERIAL PRIMARY KEY,
  cost_type TEXT NOT NULL DEFAULT 'fixed',   -- fixed=公司固定成本 chain=链条费 reimburse=报销费 other=其他支出
  group_name TEXT NOT NULL DEFAULT '',       -- fixed:公司名称 chain:品种(化肥/橡胶…) reimburse/other:留空
  item_name TEXT NOT NULL DEFAULT '',        -- fixed:房租（含水电）/人力成本/代理记账费/税费/其他 chain:链条费/货转仓储费/城投公司利润留存 reimburse:业务招待费/差旅费/礼品… other:自填明细名
  period TEXT NOT NULL DEFAULT '',           -- 年'2025' / 季度'2026-Q1' / 月'2026-10'
  amount NUMERIC NOT NULL DEFAULT 0,         -- 单位：元
  remark TEXT DEFAULT '',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE finance_costs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "允许匿名读取" ON finance_costs FOR SELECT TO anon USING (true);
CREATE POLICY "允许匿名插入" ON finance_costs FOR INSERT TO anon WITH CHECK (true);
CREATE POLICY "允许匿名更新" ON finance_costs FOR UPDATE TO anon USING (true) WITH CHECK (true);
CREATE POLICY "允许匿名删除" ON finance_costs FOR DELETE TO anon USING (true);
```

### 4.3 期间模型（period 字段）

三种粒度混存，字符串格式：
| 粒度 | 格式 | 示例 | 汇总归属 |
|------|------|------|---------|
| 年 | `YYYY` | `2025` | 小计 + 该年"全年"列 |
| 季度 | `YYYY-Qn` | `2026-Q1` | 小计 + 该年"全年"列（2026-11-19 修订：汇总表已无季度列，季度粒度不进任何月列；录入端已取消季度档，见防呆） |
| 月 | `YYYY-MM` | `2026-10` | 小计 + 该年"全年"列 + 对应月份列（1-12月） |

**汇总表列映射**（所选年=Y，列从左到右）：小计 | {Y−1}全年 | {Y}全年 | 1月 | 2月 | … | 12月 | [追加月份列…]（共 15 固定列，超宽沿 .stats-table-wrapper 横向滚动；2026-11-19 用户拍板放弃与 Excel 2026 视图布局对齐，见决定 #21；追加列见 5.2①）
- 小计 = 年份 ≤ Y 的全部记录（含无年份/无完成时间的孤儿记录；**晚于 Y 的记录不计入**，只可能出现在追加月份列中）
- {Y−1}全年 = 年份==Y−1 的全部记录（**任意粒度**）——2027 年切换到 2027 视图时，该列自动变为"2026全年"并能正确汇总 2026 的季度/月度数据，不存在"跨年空列"
- {Y}全年 = 年份==Y 的全部记录（任意粒度）
- 月列（n=1-12） = 年份==Y 且 月粒度 且 月份==n；收入侧完成时间能解析出年+月的记录视同月粒度（2026-11-19 修订）
- 季度粒度记录（含历史 2026-Q1/Q2/Q3） = 只进"全年"列与小计，不进任何月列（季度列已取消）
- 追加月份列 = period/完成时间恰为该月的记录（任意年份，可跨年）
- 自洽校验（测试断言用）：小计 = {Y−1}全年 + {Y}全年 + 无年份孤儿 + 更早年份记录（如有）；{Y}全年 − Σ(1月..12月月列) = Y 年年粒度+季度粒度记录之和
- 防呆：期间选择器只提供"全年/月"两档（2026-11-19 修订：12 个月列已固定显示，季度档整体取消——新录季度粒度记录在任何月列都看不见，会重现"各列之和≠小计"的数字打架；历史季度数据保留、只进全年列+小计）；同一年既录"全年"一笔又录月明细会重复计数，录入界面加文字提示

- 历史数据按 Excel 原粒度导入：2025 各条 → `2025`；2026 Q1/Q2/Q3 各条 → `2026-Q1/Q2/Q3`（12 月列版下只进全年列+小计）；2026 年 10 月起财务按月录入（用户 2026-11-19 改 12 个月列的依据）
- 汇总页年份切换（默认当前年 2026）：可选年份 = 数据中出现过的年份 ∪ 当前年
- 收入侧期间归属：完成时间 time 经 doneTimeVal() 解析出年/月 → 月粒度进对应月份列（1-12月；2026-11-19 修订：不再按日历季度归属）。time 为空或解析不出年份 → 只计入"小计"列，不进年/月列，且明细行标黄提示补时间

## 6. 历史数据导入

1. Python 脚本（放 `e:\tmp`，不进仓库）解析 xlsx 的 3-2/3-3/3-4 三表：
   - 3-2：16 公司 × 5 类目 ×（2025全年 + 2026Q1/Q2/Q3 有值单元格）→ cost_type='fixed'
   - 3-3：2 品种 × 3 明细 × 有值期间 → cost_type='chain'
