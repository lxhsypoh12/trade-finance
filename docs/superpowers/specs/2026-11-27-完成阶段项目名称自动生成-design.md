# 完成阶段「项目名称」自动生成 — 设计文档

日期：2026-11-27
状态：用户已批准（三项决定问答 + 方案整体「通过」）

## 意图与原因

完成阶段统计表第一列「项目名称」一直靠手填，格式不统一：规模写法有（1亿）/（5000W）/（4.5亿）/（3000万）多种，个别名称夹杂贸易方公司名，还有 1 条漏填空白。用户要求改为系统按「金融机构+完成时间+业务类型（业务规模）」自动拼接生成，统一口径、免手工、防漏填。下游（Excel 导出、财务看板项目收入明细、PDF 打印）读同一字段，自动受益。

## 目标

- 完成表「项目名称」由系统自动生成并落库，格子只读
- 生成时机两处：①中标→完成迁移时随新记录生成；②完成表内改动 完成时间/业务类型/业务规模 任一格，保存时重新生成（与源字段合并同一次 PATCH，不多发请求）
- 拼接格式（用户选定「规整拼接＋亿/万自动换算」）：
  - `金融机构原样 + 完成时间规整6位年月 + 业务类型原样 + （规模）`
  - 时间规整：提取数字，5 位补月零（`2025/7`→`202507`），6 位原样（`2026/05`→`202605`），其余位数用修剪后的原文
  - 规模：amount≥10000 显示 `X亿`（parseFloat 去尾零，如 45000→4.5亿、10000→1亿、19700→1.97亿）；<10000 显示 `X万`；全角括号包裹
  - 例：`四川金控202507跑量/受托支付（1亿）`、`民生银行202602银承-回报（4.5亿）`、`农行德阳202609银承-回报（5000万）`
  - 空字段该段留空拼接不报错；amount 空/0/非法时括号段整个不输出（构建者细则，Claude 定）

## 非目标

- 不动存量：38 条老记录名称保持手写原样，除非其源字段日后被改动（用户决定）
- 不改投标/中标表、LOAN_BIZ_TYPES、飞书推送脚本（经排查推送不读 project_name）
- 不对「完成时间」字段本身做强制校验——仍是自由文本，只在生成名称时规整

## 反目标（出现即失败）

- 老记录被静默批量改名
- 项目名称格仍可手输，形成手动/自动双口径
- Excel 导出、财务看板收入明细因本改动错位或崩溃

## 约束

- 纯前端单文件应用，改动限于 `贸易金融业务管理系统（Supabase）.html`（同步 index.html）
- project_name 仍落库存储，trade_stats 表结构零变更
- 沿用 cellUpdate onblur 即存机制

## Approaches

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 生成时计算＋落库 | 迁移/改源字段时算好名称，随源字段同一次 PATCH 写 project_name | **选定**：下游三处（Excel/财务看板/PDF）零改动；老记录天然不受影响 |
| B. 显示时现算不落库 | 各消费端展示时自行拼接 | 否决：需改三处消费端易漏；老记录会当场全变新格式，违背「老记录不动」 |
